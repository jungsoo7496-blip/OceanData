# 보안 규칙

## 테넌트 격리
- 모든 조회·변경은 토큰의 organization_id로 범위를 강제한다. 저장소(repository) 계층에서 필터를 적용한다. 라우터마다 따로 거르는 방식에 의존하지 않는다.
- 다른 기관의 리소스를 요청하면 존재 여부를 숨기기 위해 404를 돌려주고 감사 로그에 남긴다.
- 목록·검색·자동완성·집계는 권한 범위 필터를 적용한 뒤 계산한다. 결과 건수·빈 결과 응답 시간 차이로 다른 기관 데이터의 존재가 드러나지 않게 한다.
- organization_id는 인증 정보에서만 정한다. 요청 본문·쿼리·헤더로 받은 기관 ID로 범위를 바꾸지 않는다.
- 운영자라도 L0 원본 바이너리는 긴급 열람 승인(break-glass grant)이 있을 때만 접근한다.
- 새 엔드포인트마다 교차 기관 접근 테스트를 추가한다 (T01).

## 사전 서명 URL
- 업로드 파트 URL 유효시간 기본 15분, 다운로드 URL 기본 5분 (설정값).
- URL은 애플리케이션 로그·감사 로그·오류 메시지에 남기지 않는다 (쿼리 문자열 제거).
- 다운로드 URL 발급 사실은 감사 로그에 남긴다.

## 비밀정보·로그
- 토큰, API 키, 비밀번호, 사전 서명 URL, 개인정보(이름·연락처·얼굴 이미지)를 로그에 남기지 않는다.
- API 키·기기 자격증명은 해시로만 저장하고 발급 시 한 번만 보여준다.
- 원래 파일명은 객체 키에 넣지 않는다 (파일명에 개인정보가 섞일 수 있다).

## 감사 로그 (반드시 기록)
로그인 실패, 권한 거부, 교차 기관 접근 시도, 자산 상세 조회, 다운로드 URL 발급, 공유 등급 변경(사유 포함), data_role 변경, 이용 승인·철회, 긴급 열람, 정책 변경, 삭제·보류, 기기 등록·폐기, 역할 변경
- 감사 로그 테이블에는 애플리케이션 DB 계정의 UPDATE/DELETE 권한을 주지 않는다.
- 각 행은 직전 행의 해시를 포함한다 (해시 체인). 체인 검증 명령을 제공한다.

## 입력 검증
- 모든 입력은 Pydantic / JSON Schema로 검증한다. 경로 조작(`../`)과 제어 문자를 차단한다.
- 업로드 파일의 형식은 신고된 MIME이 아니라 내용(매직 바이트)으로 판별한다.

## 공공 SW 개발보안
- 공공 정보시스템 SW 개발보안(시큐어코딩) 기준의 보안약점을 피한다. CI에 정적분석(Python: bandit 또는 semgrep, Go: gosec, TS: eslint 보안 규칙)과 의존성 취약점 검사를 넣는다.
- 웹 화면은 한국형 웹 콘텐츠 접근성 지침(KWCAG) 준수를 목표로 한다.

## 에이전트
- 기기 자격증명은 OS 보안 저장소(Windows DPAPI 등) 또는 권한 0600 파일에 둔다.
- 서버 인증서 검증을 끄는 옵션을 만들지 않는다. 사설 CA 지정만 허용한다.
- 자동 업데이트 바이너리는 서명 검증을 통과해야만 적용한다.
