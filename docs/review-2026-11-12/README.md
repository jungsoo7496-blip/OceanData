# 2026-11-12 점검 기록 — 지시서 12번 독립 검토 (실제 에이전트 E2E + 병합분 5곳 + 커밋 시점 변경)

지시서 5번·12번을 이어받아 진행한 점검이다. 이 폴더는 **무엇을 찾았고, 무엇을 고쳤고, 무엇이 남았는지**와 재현 파일을 모은다.
진행 상황의 최신 요약은 루트 `HANDOFF.md`의 '남은 일'이다. 이 문서는 근거 자료다.

방법: 검토마다 서로 다른 보조 에이전트가 **병합 전 코드를 읽기 전용으로** 검토하고, 의심은 합성 데이터로 재현했다(저장소를 고치지 않고, 임시 DB를 만들어 지웠다).
내가 재현 시험을 `backend/tests`·`agent/`에 먼저 써서 **수정 전 코드에서 실패하는 것을 확인한 뒤** 고쳤다. 고치지 않은 것은 이유와 방향을 아래에 적는다.

| 점검 | 대상 | 결과 |
|---|---|---|
| A. 실제 Go 에이전트 E2E | 격리된 로컬 스택(PostgreSQL·SeaweedFS·API·워커·Mosquitto), 실제 에이전트 바이너리 | 기기 범위 축소로 에이전트가 깨지지 않음. 버그 1건(F1) 고침 |
| B. 클립 내보내기 권한·업로드 정리 트랜잭션 | `assets.py`·`clips.py`·`ingest.py`·`retention.py`·`lifecycle.py` | 클립 권한·쿼터·상한은 이상 없음. 삭제·검증·정리에서 12건 |
| C. 웹훅 전송 격리 | `webhooks.py`·`monitoring.py` | 7건 |
| D. 계약 검증기·XLSX 수식 방어 | `contracts.py`·`normalize.py`·`report_renderers.py` | 수식 방어는 이상 없음. 검증기·내보내기에서 10건 |
| E. 커밋 시점 변경(`gpt/05-commit-before-response`) | `deps.py`·`idempotency.py`·`errors.py` | 핵심 주장은 깨지 않음. 7건 → 항목 5 브랜치에서 처리 |

상태: **고침**(수정 + 재현 시험) / **완화**(일부만 고침) / **미완**(이유와 방향만 기록) / **사람 결정** / **정보**(동작이 맞고 문서로 남김).
재현 파일은 `repro/`다 (아래 '재현 파일 쓰는 법').

## A. 실제 에이전트 E2E (`repro/agent-e2e/`)

12개 에이전트 엔드포인트(등록·토큰·정책·매핑·하트비트·건강·업로드 생성/파트/완료·영수증·관측값)가 모두 2xx. 허용된 403은 일부러 넣은 부정 탐침(42건)뿐이고 에이전트 경로에는 403·5xx가 0건이다.
강제 종료(`kill -9`) 뒤 남은 파트만 보내 이어서 완료, 감사 체인 정상(97행). 다른 장치(같은 기관의 다른 수집기와 다른 기관의 수집기)의 영수증·업로드·정책·건강·매핑을 지목한 48개 요청은 모두 404였고 각자 자기 자원은 200이었다.

| # | 내용 | 상태 |
|---|---|---|
| F1 | 같은 내용을 다른 이름으로 복사하면 Idempotency-Key는 같고 본문(파일명·경로)이 달라 409 `IDEMPOTENCY_CONFLICT`가 나고, 에이전트가 그 파일을 재시도 없는 실패로 둔다 | **고침** (ADR-0054, `idempotency_key_test.go`). 키를 본문에서 만든다 |
| F2 | 생성된 Go 클라이언트에 이벤트 작업이 없다(`include-operation-ids`에 `createEvent` 없음). 에이전트는 `/v1/events`를 부르지 않는다 | 정보 — 장치 자격의 `event:write`는 현재 소비자가 없다 |
| F3 | `complete` 직후 영수증 조회는 무결성 검증이 끝날 때까지 404다(약 5초, 3~4번) | 정보 — 설계대로(권한 거부 아님) |
| F4 | Keycloak 없이는 `/readyz`가 503(`idp: failed`)이다. 장치 API는 정상 | 정보 |
| F5 | 요구사항 02-5.5 문구는 업로드·관측값·이벤트·하트비트·정책만 나열하는데 장치 허용 목록에는 `me:read`·`mapping:read`·`asset:receipt`·`upload:read`·`agent_health:read`도 있다 | 정보 — 에이전트가 쓰는 것이라 코드 변경 없음 |

확인하지 못한 것: Keycloak·사용자 토큰 흐름, Windows(DPAPI·서비스·exe), TLS·`--ca`, 자동 갱신, 호출 제한, 5MiB 초과 파트·34MB 초과 파일, C3 카메라의 영상 원본(시드에 없음), 72시간 오프라인, 실제 MQTT 인증.
(CSV `sensor_parse`는 센서 매핑이 `mqtt_json`이라 관측값이 안 나왔다 — 이 변경과 무관.)

## B. 클립 내보내기 권한·업로드 정리 (`repro/clip-upload/`)

**클립 권한·쿼터·상한은 이상 없음**: 역할 표(운영자·열람자·검토자·소비자 403, 타 기관 404+감사, 장치·API 키 거부), 원본 외 소스·격리 소스 409, 비식별·민감도 상속, 구간 검증(NaN·무한대·범위 밖 400),
동시 10요청에서 상한 3(202 3건·429 7건·작업 3·감사 3), 같은 구간 6요청에 작업 1, 같은 작업 두 번 실행해도 자산·객체·쿼터 한 번. 25초 무작위 부하(클립·삭제·만료 집행·업로드·정리, 6스레드)에서 교착·오류 없음, 쿼터 불변식 유지.

## D. 계약 검증기·XLSX/PDF/HWPX (`repro/validator-export/`)

**핵심 주장은 유지**: 약 5만 2천 개 변이 문서에서 떨어진 스키마 오류마다 같은 포인터(또는 /location 아래)에 ERROR 대체가 있었고 '무효 → 유효'로 뒤집힌 경우가 0건.
경고(WARNING)는 아무것도 가리지 않고, 포인터는 조각 단위로 비교한다(`/observations/10` ≠ `/observations/1`). RFC 6901 이스케이프가 맞다. 46개 패턴의 ReDoS는 최악 12ms. 출력은 `PYTHONHASHSEED`에 무관하다.
**XLSX 수식 방어는 이상 없음**: 26가지 시작 문자 변형에서 `<f>` 0개, LibreOffice 실행으로 확인, 하이퍼링크·주석·정의된 이름 등 사용자 제어 부분 없음.
**PDF**: 사용자 문구는 모두 `html.escape` 뒤 요소 텍스트로만 들어간다. 11개 주입 시도가 태그·속성·CSS를 추가하지 못했고 카나리 서버에 요청이 오지 않았다.

|---|---|---|---|
| V1 | 중간 | NaN·±Infinity가 숫자로 통과해 저장되고, 그 구간을 포함한 보고서 생성이 500이다 | **고침** (ADR-0056, `test_contract_validator_hardening.py`·`test_contract_validator_api.py`) |

## E. 커밋 시점 변경 (`repro/commit-timing/`)

핵심 주장은 깨지 않았다: 실제 uvicorn + 원시 소켓에서 응답 첫 바이트가 `commit` 반환 후 0.7~1.3ms에 도착(제어 실험은 커밋 끝 1.2초 전). 159개 API 경로 중 156개가 `get_db`를 쓰고 모두 function 범위, 다른 yield 의존성 없음.
통합 시험 209개 동안 1181 요청을 외부 ASGI 탐침으로 감싸 한 요청에 세션 둘·응답 후 커밋이 0건. 같은 키 동시 요청의 교착 사이클 없음, `lock_timeout` 누수 없음.
항목 5 브랜치(`gpt/05-commit-before-response`)에서 모두 처리했다(HANDOFF 0장 -1ao). K1은 대기자 상한(프로세스당 8개)·대기 2초·`/healthz` async, K2는 FastAPI 0.121 하한, K3는 `complete`의 저장소 상태 기반 재시도, K4는 로그·지표, K5는 예제 클라이언트, K6은 조립된 앱 기준 시험, K7은 ADR 문구.

## 사람이 정할 것

1. **삭제를 2단계(outbox)로 할지.** 지금은 객체 삭제를 확인한 뒤에야 증명을 발급한다(요청이 503이면 재시도). 2단계는 더 견고하지만 증명에 '삭제 요청됨'과 '삭제 확인됨'이 갈려 증명의 법적 의미가 바뀐다 (C1).
2. **`RECEIVED`에서 실패로 가는 길.** 검사기가 오래 없을 때 자산이 `RECEIVED`에 영구히 남고 예약이 샌다. domain.md 5장 상태표에 `RECEIVED → FAILED(예약 해제)`를 더하거나 운영자 재투입 경로를 둘지 (C2).
3. **웹훅 구독 비활성화의 의미와 전송 구조.** 독살 이벤트 처리(W5)와 라운드 장벽 제거(W1)는 함께 정해야 한다. ADR-0030·0041 개정.
4. **미완성 멀티파트 청소 방식.** 저장소 수명주기 규칙을 쓸 수 있는지(SeaweedFS **확인 필요**)와 앱이 재시도 목록을 둘지 (C4).
5. **요청 본문 크기 제한의 자리.** 앱 미들웨어로 둘지 프록시에만 둘지 (V5).

## 재현 파일 쓰는 법

`repro/` 아래 파일은 **참고용이다 — 저장소의 시험이 아니다**(`backend/tests` 밖이라 pytest가 모으지 않는다). 점검 기계의 임시 경로(`/tmp/...`)와 임시 DB 이름을 가리키는 곳이 있어 그대로는 돌지 않을 수 있다.
고친 항목은 같은 내용을 `backend/tests`·`agent/internal/core`의 정식 시험으로 다시 썼다(각 ADR의 '시험'). 아직 고치지 않은 항목의 재현을 다시 보려면 파일을 `backend/tests/integration/`으로 복사해 자기 DB로 돌린다:

```bash
cd backend
PGPASSWORD=change-me-owner psql -h 127.0.0.1 -U marine_owner -d postgres -c "CREATE DATABASE marine_repro"   # 운영 DB·marine은 쓰지 않는다
cp ../docs/review-2026-11-12/repro/clip-upload/test_rv12_upload.py tests/integration/
TEST_DATABASE_URL=postgresql+pg8000://marine_owner:change-me-owner@127.0.0.1:5432/marine_repro \
  .venv/bin/pytest -q -p no:cacheprovider -p no:logging -s tests/integration/test_rv12_upload.py -k sweeper
```

재현 시험은 `print("OBS …")`로 관측을 남기는 방식이 많다(고쳐지기 전 동작을 보이려는 것이라 단언이 없다). 고칠 때는 정식 회귀 시험으로 다시 쓰고 이 폴더의 복사본은 지운다.
