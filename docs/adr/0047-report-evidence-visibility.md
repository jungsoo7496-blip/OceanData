# ADR-0047: 보고서 근거와 원래 파일 경로의 조회 범위

- 상태: accepted
- 날짜: 2026-11-07
- 관련: 10번 요구사항 3.2, 5.3, 6.2, 7.1

## 맥락

제출된 보고서의 지표나 근거 손상 목록에 비공개 자산 ID가 포함될 수 있다. 권한이 있는 파생 자산의 `provenance.parent_asset_ids`에도 숨겨진 원본 ID가 들어갈 수 있다. 원래 파일명과 상대 경로에는 개인정보가 포함될 수 있으므로 자산을 볼 권한과 별도로 공개 범위를 정한다.

## 결정

- 보고서 응답의 `metrics[].sources.asset_ids`와 역추적에 나타나는 근거 자산 ID를 조회자의 현재 Tenant_Guard 범위로 거른다. 지표 출처, 이벤트 연결, 자산 목록, 계보 원본에 같은 기준을 적용한다. 배정 사업의 제출본을 보는 관리기관 열람자에게는 그 사업의 L1 이상 자산만 보인다. 역추적의 `hidden_count`는 가린 근거 자산의 수를 나타낸다.
- 보고서 소유 기관은 삭제된 원인을 포함한 근거 손상 이력을 볼 수 있다. 다른 기관 조회자와 관리기관 열람자에게는 현재 조회할 수 있는 원인 자산만 `damage`에 표시한다. 가린 원인만 있는 경우에도 `evidence_damaged`는 유지한다. PDF·XLSX의 근거 손상 안내에도 같은 범위를 적용하고, 표시할 원인이 없으면 ‘근거 손상’ 문구만 넣는다.
- 자산 응답의 `provenance.parent_asset_ids`도 Tenant_Guard 범위로 거른다. 원래 파일명과 상대 경로는 소유 기관의 `ORG_ADMIN`·`ORG_MEMBER` 사용자 또는 `PLATFORM_OPERATOR` 사용자에게 공개한다. 같은 기관의 API 키와 관리기관 열람자·검수자·이용기관의 응답에서는 이 두 필드를 생략한다. 이 규칙은 자산 조회 권한을 부여하지 않는다.

지표 계산과 원천 기록에는 전체 근거가 필요하고, 소유 기관은 손상 원인을 추적할 수 있어야 한다. 저장 시 근거를 제거하면 이후 권한 변경이나 손상 조사에 대응할 수 없으므로, 요청 시점의 응답에만 필터를 적용한다.

## 결과

승인 스냅숏에는 전체 원천 참조를 보존한다. 자산의 원래 파일명·상대 경로도 내부 메타데이터에 저장한다. 기존 데이터와 저장 구조를 사용하므로 마이그레이션은 없다.

회귀시험은 `backend/tests/acceptance/test_t11_reports.py`의 제출본·역추적·근거 손상 사례와 `backend/tests/integration/test_asset_provenance.py`의 역할별 자산 응답을 확인한다. 실제 관리기관 HWPX 양식의 출력과 열기 검증은 양식 확보 뒤 진행한다(T11-f).
