# ADR-0060: 격리 사용량은 격리 존에 있는 객체로 센다

- 상태: accepted
- 날짜: 2026-11-12
- 관련: 04번 요구사항 1.5·4.4·5.2·5.3, domain.md 9장(사용량 = 등록 객체 + 격리 + 예약 + 신청 백업), ADR-0058(검증 재개), 지시서 12번 클립·업로드 검토 C11

## 맥락

무결성 검증이 자산을 격리하면 객체를 격리 존으로 옮기고(`tiers.relocate`) 예약을 격리 사용량(`quarantine_bytes`)으로 정산했다. 옮기기가 실패해도(저장소 오류) 상태는 격리로 두는데,
**정산은 옮겼는지와 상관없이 격리 사용량으로 했다.** 반면 삭제(`retention.delete_assets`)는 자산의 `storage_zone`이 `QUARANTINE`일 때만 격리 사용량에서, 아니면 사용량(`used_bytes`)에서 뺀다.
그래서 격리 이동이 실패한 자산을 지우면 격리 사용량이 그대로 남아 쿼터가 영구히 줄었다(검토 C11).

같은 원인으로 두 가지가 더 어긋났다.
- **보완 뒤 재검증이 바이트를 두 번 셌다.** 재검증 여부를 `storage_zone == 'QUARANTINE'`으로만 판단해, 원래 존에 남은 격리 자산(회차 미상 등)을 보완하면 처음 검증을 이어 하는 것(ADR-0058 resume)으로 보고
  사용량을 한 번 더 더했다. 격리 사유도 지워지지 않아 `READY_PRIVATE`인데 `quarantine_reason`이 남았다.
- **재검증이 같은 자리로 옮기려 할 수 있었다.** 정식 위치와 키가 같으면 `move_object`가 복사 뒤 원본을 지워 객체를 잃는다.

손상 감지(`pipeline` 손상 격리)는 이미 옮기기에 성공했을 때만 사용량을 격리 사용량으로 옮겨, 존 기준과 맞았다.

## 결정

1. **격리 사용량은 격리 존(`storage_zone = 'QUARANTINE'`)에 있는 객체의 바이트다.** 격리로 옮기지 못한 객체는 원래 존에 있으므로 사용량으로 센다. 삭제·재검증·손상 격리가 모두 이 기준을 쓴다.
2. 처음 검증에서 격리하면 옮긴 결과(존)를 보고 예약을 격리 사용량 또는 사용량으로 정산한다.
3. **재검증은 '격리 사유가 있는 VALIDATING'도 포함한다**(존이 격리가 아니어도). 재검증에서 다시 격리되며 이번에 옮겨지면 사용량 → 격리 사용량으로 옮기고, 통과하면 격리 존에 있던 것만 격리 사용량 → 사용량으로 옮긴다.
4. 재검증 통과 때 객체가 이미 정식 위치(같은 계층·존·키)에 있으면 옮기지 않는다.

버린 대안: 삭제가 상태(`ingest_status = 'QUARANTINED'`)를 보고 빼게 하기 — 손상 격리는 이동 실패 시 사용량에 남겨 두므로 상태 기준이면 그쪽이 새고, 대사(`reconcile`)가 존별 객체를 세는 것과도 맞지 않는다.
격리 이동을 따로 재시도하는 작업 — 재검증이 이동을 다시 시도하므로 이번 범위에서는 두지 않는다(옮기지 못한 객체는 원래 존에서 사용량으로 정확히 센다).

## 결과

좋아지는 점: 격리 이동이 실패한 자산을 지워도 쿼터가 돌아온다. 보완 뒤 재검증이 바이트를 한 번만 세고 격리 사유를 지운다. 같은 자리 이동으로 객체를 잃지 않는다.

감수할 점: 격리 이동이 실패한 자산은 사용량 내역에서 '격리'가 아니라 '저장'으로 보인다(`GET /v1/usage`의 `breakdown`). 상태(`ingest_status`)는 격리 그대로라 공개·처리에서는 계속 격리로 다룬다.
이미 운영 중인 DB에 이 문제로 남은 격리 사용량은 고치지 않는다(마이그레이션 없음) — 일일 대사(`reconcile`)의 차이 알림으로 드러나며, 필요하면 운영자가 기관별로 다시 계산한다.

되돌리는 방법: `IntegrityVerifier.verify`의 `revalidate` 조건·`was_in_quarantine_zone` 분기·같은 자리 이동 검사를 지운다. 계약·마이그레이션 변경 없음.

시험: `tests/integration/test_quarantine_accounting.py` 3개 — 격리 이동 실패 뒤 삭제하면 사용량 0, 이동 실패한 회차 미상 자산의 보완·재검증이 한 번만 셈(객체가 회차 위치로 옮겨지고 옛 키는 없음),
재검증에서 다시 격리되며 이번에 옮겨지면 사용량 → 격리 사용량. 수정 전 코드에서 3개 모두 실패하는 것을 확인했다.
