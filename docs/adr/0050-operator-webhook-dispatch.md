# ADR-0050: 운영자 알림 웹훅 전송 격리

- 상태: accepted
- 날짜: 2026-11-11
- 관련: 11번 요구사항 3.1~3.4, ADR-0017, ADR-0041

## 맥락

운영자 알림 웹훅이 감시 규칙 평가 중 응답 본문까지 기다렸다. 수신기가 응답을 천천히 보내면 단계별 HTTP 제한시간 안에 일부 바이트를 계속 받으면서 감시 트랜잭션과 워커 작업 처리가 지연됐다.

## 결정

- 워커는 감시 트랜잭션이 커밋된 뒤 전송 내용을 프로세스별 100건 메모리 FIFO 큐에 넘긴다. 전용 전송 스레드가 한 건씩 처리하며, 워커는 큐 공간이나 응답을 기다리지 않는다. `python -m app.cli watch`는 커밋 뒤 같은 전송 함수를 동기 호출한다.
- 한 건은 DNS 조회부터 연결·TLS·요청·응답 헤더까지 5초 이내에 처리한다. HTTP 상태를 확인한 뒤 연결을 닫아 응답 본문을 읽지 않는다. 프로세스에서 DNS 조회를 수행하는 데몬 스레드는 최대 4개다. 기한이 지난 DNS 조회는 실제 반환할 때까지 슬롯을 사용하며, 모든 슬롯이 차 있으면 새 DNS 조회를 시작하지 않는다.
- 운영자가 설정한 `ALERT_WEBHOOK_URL`을 사용한다. HTTPX가 프록시 환경변수를 적용하며, 리디렉션 응답은 전송 실패로 처리한다. `ALERT_WEBHOOK_SECRET`을 설정하면 기존 HMAC 서명 헤더를 붙인다.

## 결과

수신기가 늦어도 워커는 다음 작업을 처리할 수 있다. 운영자 웹훅은 한 건당 한 번을 시도하는 알림 채널이다. 큐가 가득 차거나 프로세스가 종료되면 일부 알림이 유실될 수 있다. 장애 기록은 DB에서 확인할 수 있다. 기존 API와 DB 구조를 사용하므로 마이그레이션은 없다.

회귀시험은 로컬 합성 수신기를 사용한다. `test_operator_webhook_transport.py`는 응답 본문 보류, 느린 헤더, DNS 지연, 환경 프록시와 서명을 확인한다. `test_operator_webhook_worker.py`는 수신기가 헤더를 보류하는 동안 장애 커밋과 다른 작업 완료를 확인한다.
