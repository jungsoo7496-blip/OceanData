# ADR-0040: 에이전트 정책 숫자의 기술 상한

- 상태: accepted
- 날짜: 2026-11-06
- 관련: 06번 요구사항 2.2, 3.1, 4.2, 5.1, 6.1, 7.3, 9.1

## 맥락

정책의 큰 하트비트 주기를 나노초로 바꾸면 `time.Duration`이 넘쳐 하트비트를 쉬지 않고 보낼 수 있다. 큰 재시도 간격도 SQLite에 저장하는 `UnixNano` 재시도 시각을 넘길 수 있다. 서버는 예전 정책 값을 읽고 상태 시각을 계산하므로 새 쓰기만 검증해서는 충분하지 않다.

## 결정

정책 시간의 기술 상한은 2,147,483,647초로 둔다. 원천 장비의 현장 보존 일수는 초로 환산해 이 범위에 드는 24,855일까지다. 수집 주기, 전송 속도(kbps), 규칙 순위는 32비트 정수 상한을 사용한다. 파트 동시 전송 수 상한은 업로드 파트 번호의 최댓값인 10,000이다. 계약과 서버의 정책 저장·초안 입력·장비 등록에서 같은 범위를 검사한다.

수집기 정책 응답은 저장본과 기본 정책 모두 배포 전에 현행 계약으로 검사한다. 이전 범위 밖 값에는 필드 위치와 함께 422 RULE_VIOLATION을 반환한다. 에이전트는 잘못된 새 정책을 저장하거나 적용하지 않고, 유효한 이전 정책이 있으면 계속 사용하며 POLICY_INVALID를 보고한다. 동시 전송 수가 생략되면 기존 기본값 4를 사용한다.

에이전트의 정수 초 변환은 `timex.Seconds`에서 처리한다. 계약 검사를 우회한 변환, 숫자로 된 Retry-After, 토큰 수명에도 같은 시간 상한을 적용한다. MP4 촬영시각은 mvhd 버전과 해당 상자 안에서 읽을 수 있는 길이를 확인한다.

배포할 때 조용히 값을 자르면 저장된 운영자 정책과 실제 동작이 달라진다. 잘못된 정책의 배포를 거부하고 운영자가 수정한 새 버전을 발행하도록 한다. 기존 장비·정책·초안 기록은 보존한다. 초안 미리보기에 이전 값을 표시하고 적용 전에 위반을 보여 준다. 카드에서 가져온 범위 밖 값은 확인 필요로 둔다. 저장된 하트비트 주기가 범위 밖이면 서버의 상태·경보 계산에 기본값 60초를 사용한다.

## 결과

기존 유효 정책은 그대로 사용한다. 상한을 넘는 이전 정책은 운영자가 `set-policy`로 새 버전을 저장하거나, 장비·전송 설정에 해당하면 정책 초안에서 정정한 뒤 적용할 수 있다. 유효한 로컬 정책도 없는 에이전트는 새 유효 정책을 받을 때까지 대기한다. 기존 저장본을 수정하는 마이그레이션은 없다.
