# ADR-0046: 업로드 중인 자산·회차 삭제

- 상태: accepted
- 날짜: 2026-11-07
- 관련: 08번 요구사항 3.4, 3.6, 3.7, 5.1, 5.2 및 04번 요구사항 1.5, 3.4

## 맥락

자산·회차 삭제가 미완료 멀티파트를 남겨 두면 삭제 증명을 발급한 뒤에도 업로드가 완료될 수 있다. 이때 객체가 삭제된 자산 기록과 연결되지 않은 채 저장소에 남고 예약 용량도 해제되지 않는다. 이미 수신한 객체는 검증 작업이 읽고 상태와 쿼터를 확정할 수 있으므로 같은 방식으로 중단할 수 없다.

## 결정

- 자산·회차 삭제는 원본과 파생 자산을 잠근 뒤 상태를 확인한다. `UPLOADING` 자산의 세션은 `SKIP LOCKED`로 잠근다. 완료·만료가 세션을 먼저 잠그는 경로와 교착하지 않도록 세션 잠금을 즉시 얻을 수 없거나 대응 세션이 없으면 요청 전체에 409를 반환한다.
- S3 멀티파트 중단 뒤 해당 키에 완성 객체가 없는지 확인한다. 저장소 오류로 확인할 수 없으면 `Retry-After`와 함께 503을 반환하고, 이미 완성 객체가 있으면 409를 반환한다. 확인에 성공하면 세션을 `ABORTED`로 바꾸고 예약을 한 번 해제한다. 자산 기록은 소프트 삭제하고 삭제 증명을 연결한다.
- `RECEIVED`·`VALIDATING` 자산이 하나라도 있으면 409로 요청 전체를 거부한다. 검증이 끝난 뒤 재시도한다. 보존 만료 미리 보기와 실행에서는 `UPLOADING`·`RECEIVED`·`VALIDATING` 자산을 제외한다.

검증 중인 객체를 즉시 지우려면 무결성 작업을 별도로 중단하고 상태·쿼터 갱신을 조율해야 한다. 검증을 마친 뒤 삭제하도록 해 이미 수신한 객체와 그 사용량을 기존 절차에서 함께 정리한다. 아직 완성되지 않은 업로드는 기존 취소 동작을 재사용해 삭제 요청 안에서 정리한다.

## 결과

삭제 증명의 객체 목록에는 삭제 대상으로 처리한 완성 객체의 키와 해시를 적는다. 중단한 업로드는 이 목록과 백업 소멸 예정일의 산정에서 제외한다. 등록·격리 사용량은 완성 객체에 대해서만 차감한다. 중단된 세션의 완료 요청은 410이다. 기존 테이블을 재사용하므로 새 마이그레이션은 없다.

회차 삭제 중 일부 멀티파트를 중단한 뒤 다른 중단이 실패하면 DB의 세션·예약·삭제 증명 변경은 롤백된다. 이미 중단한 멀티파트는 저장소에서 종료 상태로 남는다. 재시도 시 이미 없는 멀티파트도 확인해 정리를 이어갈 수 있다.

일반 수신 객체가 `VALIDATING`으로 커밋된 뒤 스토리지 스트림이나 검사기에서 예외가 나면 검증 상태에 남을 수 있다. 이 경우 검증 상태를 복구할 때까지 삭제도 보류된다. 등록 객체의 삭제 오류와 증명 정합성은 별도 경로의 문제다.

회귀시험은 `backend/tests/integration/test_lifecycle.py`에서 자산·회차 삭제, 수신·검증 중 409와 이후 재시도, 저장소 중단 오류와 완료 객체, 보존 만료 제외를 확인한다.
