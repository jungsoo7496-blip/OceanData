# ADR-0029: 긴급 열람 — 요청자 한정·대상(자산/회차) 한정·만료 시각으로 즉시 회수

- 상태: accepted
- 날짜: 2026-11-05
- 관련: 02번 요구사항 8, security.md("운영자라도 L0 원본은 긴급 열람 승인이 있을 때만"), domain.md 2장, ADR-0013

## 맥락
운영자는 모든 기관 메타데이터를 보지만 원본 바이너리는 평소 열지 않는다. 장애·사고 때는 원본을 봐야 할 수 있다.
0001 마이그레이션에 `break_glass_grants` 표만 있고 서비스·API는 없었으며, 운영자의 download-url은 항상 403이었다.

## 결정
1. **흐름**: 운영자(다중 인증)가 사유(10자 이상)·대상·기간(60초~24시간)을 적어 요청 → 다른 운영자(다중 인증)가 승인·거절 →
   승인 시각부터 기간만큼 ACTIVE. 본인 승인은 `BREAK_GLASS_SINGLE_APPROVAL`(기본 false)일 때만.
2. **범위**: 대상은 자산 하나(ASSET) 또는 실증회차(SESSION, 그 회차 자산 전부). 권한은 **요청한 운영자 한 명**에게만 생긴다
   (승인자는 받지 않는다). 원본 접근 경로는 지금 `POST /v1/assets/{id}/download-url` 하나다.
3. **감사·통지**: 요청·승인·거절·조기 종료·만료를 각각 감사하고, 승인 시 대상 기관 ORG_ADMIN에게 메일(본문에 URL·토큰 없음).
   권한으로 발급한 URL마다 `DOWNLOAD_URL_ISSUED`와 별도로 `BREAK_GLASS_ACCESS`(grant_id 포함)를 남긴다.
4. **회수**: 접근 판단은 `expires_at > now`로 하므로 기간이 끝나는 순간 막힌다. 워커 정비 주기는 상태를 EXPIRED로 맞추고 감사를 남긴다.
   조기 종료(revoke)는 새 상태 코드 없이 EXPIRED + expires_at=now. 승인 전 철회는 DENIED.
5. 상태 값은 표에 이미 있던 REQUESTED·ACTIVE·EXPIRED·DENIED만 쓴다. DB 구조 변경 없음.

## 결과
- 좋아지는 점: '원본은 평소 안 연다' 원칙을 지키면서 사고 대응 경로가 생겼다. 대상 기관이 접근 사실을 직접 본다.
- 감수할 점: 사후 검토(누가 무엇을 봤는지 기관 확인) 절차는 Runbook 05로만 — 자동 보고서는 없다. 프록시·프레임 등 다른 원본 경로가
  생기면 같은 판단(`active_grant_for`)을 붙여야 한다.
- 되돌리는 방법: 경로·권한 제거, `asset:download`에서 PLATFORM_OPERATOR 제거.
