# ADR-0019: 공유 조건 강제 위치·우회 방지, 데이터셋 버전 구성

- 상태: accepted
- 날짜: 2026-11-04
- 관련: 13번 요구사항 3, 5, 9, 10, domain.md 4·5장, `backend/app/domain/sharing_rules.py`, `backend/app/services/sharing.py`, `backend/app/services/datasets.py`

## 맥락
domain.md 4장은 공유 가능 조건을 "domain/sharing_rules 한 곳에만" 구현하라고 하고, 13번 요구사항 3.3은 API·워커·화면·관리 명령
어디서든 sharing_scope를 바꿀 때 규칙을 거치라고 한다. 또 데이터셋 버전을 만들 때 자산 사본을 DATASET 존에 두고 계보를 유지해야 한다.

## 결정
1. **판단은 순수 함수 하나**: `sharing_rules.evaluate(target, Facts, approvals)`가 미충족 조건 목록을 돌려준다. Facts에는 자산과 계보 위
   모든 조상의 variant·data_role·sensitivity를 넣어 "가장 엄격한 값 상속"과 "CORE 원본의 파생본 금지"를 판단한다. 속성 기반 시험
   (hypothesis, 무작위 속성·조상 사슬 수천 건)으로 조건을 통과한 경우 불변식이 깨지지 않음을 확인한다 (T08-c).
2. **우회 방지는 ORM 저장 직전 가드**: SQLAlchemy `before_flush`에서 sharing_scope가 **올라가는** 변경은 sharing 서비스가 표시한 것만
   통과시킨다. 새 자산은 L1까지만 바로 만들 수 있다. 내리는 변경은 언제든 허용(하향은 ORG_ADMIN 언제든). SQL 직접 UPDATE는 가드를
   지나지 않으므로 애플리케이션 코드에서 쓰지 않는다 (시험 데이터 준비에만).
3. **L3·L4는 신청 → 운영자 결정**: ORG_ADMIN 신청 때 운영자 승인 외 조건이 맞으면 IN_REVIEW로 두고, 운영자 결정 시점에 다시 평가한다.
4. **데이터셋 버전 항목은 자산 행이 아니라 항목 표**: `dataset_version_items`(원 자산 ID, 패키지 경로, DATASET 존 키, sha256)로 둔다.
   사본마다 새 자산 행을 만들지 않으므로 계보는 "항목 → 원 자산 → (조상)"으로 이어진다. 매니페스트(`source_asset_id` = 계보의 원본)는
   계약 스키마로 검사해 DATASET 존에 저장하고 sha256을 기록한다.
5. **버전 등급은 항목의 현재 등급으로 계산**: 버전 행에 등급을 저장하지 않고 항목의 지금 sharing_scope 중 가장 낮은 값으로 본다.
   하향된 자산이 든 버전은 바로 카탈로그에서 빠지고(L3 미만), 새 버전에는 규칙이 넣지 않는다.
6. **버전 생성은 요청 안에서 동기**: 항목 1000개까지. 계약의 202(작업)를 201로 바꿨다. 대용량은 작업 큐로 옮길 때 다시 결정한다.
7. **이용 신청 결정은 기관별 한 번**: 제공기관 ORG_ADMIN 결정을 기관마다 기록하고, 한 곳이라도 거절하면 DENIED로 끝낸다. 운영자 승인은
   PROVIDER_APPROVED에서만 가능하다. 약정 허용 목적 위반은 기관 수만 알린다.

## 결과
- 규칙을 바꿀 곳이 한 군데이고, 시험이 모든 경로(API·관리 명령·워커)에 공통으로 적용된다.
- 감수: 가드는 ORM 경로만 막는다. 원시 SQL로 등급을 올리는 코드는 리뷰에서 막아야 한다 (bandit·리뷰 체크리스트에 추가 권장).
- 되돌리기: 항목 표 대신 사본 자산 행이 필요해지면(사본별 메타데이터 수정 등) DATASET 변형(variant)을 계약에 추가하고 이관한다.
