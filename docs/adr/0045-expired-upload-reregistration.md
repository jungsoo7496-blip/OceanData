# ADR-0045: 만료된 업로드를 다시 신고할 때 새 세션 열기

- 상태: accepted
- 날짜: 2026-11-06
- 관련: 04번 요구사항 1.5, 2.1, 2.4, 3.2, 3.3

## 맥락

진행 중인 업로드는 바이너리가 완성되기 전부터 자산에 `has_binary`가 표시된다. 이 세션이 만료된 뒤 같은 파일을 신고하면 정리 전까지 `ALREADY_REGISTERED`가 반환되어 업로더가 등록 영수증을 기다릴 수 있었다.

## 결정

같은 파일의 업로드가 만료되면 기존 정리 경로를 호출한다. 신규 자산은 같은 파일의 새 자산·세션으로 교체하고, C0에서 시작한 자산은 기존 만료 경로에서 복원한 뒤 같은 자산 ID에 새 세션을 연다. DB에서 이전 예약 해제와 새 예약은 같은 트랜잭션에 둔다. 저장소 정리에 실패하면 503으로 재시도한다. 완료·정리는 세션을 먼저 잠그므로 자산을 이미 잠근 재신고는 `SKIP LOCKED`로 세션을 잡고 경합 시 409를 반환한다.

주기 정리까지 기다리게 두는 방법은 만료 후에도 오판을 남긴다. 별도 트랜잭션에서 정리한 뒤 다시 조회하는 방법은 같은 파일의 자산·예약 사이에 재신고가 끼어들 수 있다. 기존 정리를 재사용하고 새 상태나 마이그레이션을 두지 않는다.

## 결과

정상 만료 흐름에서는 기존 Go·웹·Python 클라이언트가 새 201 세션을 사용한다. 유효한 멱등 키의 첫 응답 재생 규칙은 유지한다. 세션 만료 직전에 만들어져 여전히 유효한 재생 기록과 이미 오판 응답을 받아 영수증 대기에 들어간 에이전트는 별도 복구 절차 확인이 필요하다. 스토리지 정리 이후 새 세션 생성에 실패하면 DB 예약은 롤백되고, 다음 정리에서 이미 제거된 멀티파트를 다시 처리할 수 있다.

체크섬 불일치 격리 재수집은 기존 격리 객체와 감사 계보를 보존할 정책 결정이 필요하다. 선택지는 HANDOFF 5장에 남긴다.
