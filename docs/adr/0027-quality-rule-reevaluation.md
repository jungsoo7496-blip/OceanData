# ADR-0027: 품질 규칙 로딩과 운영자 재평가

- 상태: accepted
- 날짜: 2026-11-05
- 관련: 03번 요구사항 10.1, 10.2, 작업 14

## 맥락

0002 마이그레이션에 품질 규칙 버전과 활성 플래그가 있다. 기존 수집과 미디어 검사는 기본 규칙만 사용했고 운영 재평가 명령이 없었다.

## 결정

- 활성 DB 규칙 한 버전을 읽어 `DEFAULT_RULES`와 병합한다. 필수 필드는 데이터 유형별로 병합한다. 활성 행이 없으면 기본 규칙을 사용하고, 활성 행이 여러 개이거나 유효하지 않은 문서면 오류를 반환한다. 촬영시각과 단위 미상은 최소 WARNING, 재생 불가는 FAILED다.
- C0 등록, 바이너리 무결성 등록, 미디어 검사의 기존 평가에서 같은 규칙 로더를 사용한다. 바이너리 검증은 상태 전이 전에 규칙을 읽어 잘못된 설정으로 자산이 VALIDATING에 남는 일을 막는다.
- 운영 CLI `reevaluate-quality`는 명시한 기관에 한해 삭제되지 않은 REGISTERED·PROXIED·READY_PRIVATE 자산을 잠근 뒤 품질을 재평가한다. 선택 범위에 자산 ID를 지정할 수 있다. 결과와 적용 버전, 확인된 처리 사실을 내부 `ingest_context`에 저장한다.
- 격리·미완료·삭제 자산과 저장 위치는 건드리지 않는다. 레거시 결과의 재생 불가 및 단위 미상 근거를 유지한다. 기존 범위 경고의 관측값이 남아 있지 않으면 해당 자산을 보존하고 `skipped_missing_facts`로 집계한다. 재평가 결과와 성공 감사를 한 트랜잭션으로 확정한다.

## 결과

기존 DB 테이블과 내부 JSON 필드를 사용한다. 공개 계약과 DB 구조가 같으므로 신규 마이그레이션/down은 해당 없다.
과거 센서 파일 전체의 관측 사실은 복원할 수 없어 저장된 사실에만 범위 규칙을 적용한다.
원복은 새 CLI 및 규칙 로딩을 제거하는 코드 되돌리기다. 과거 품질 결과를 다시 계산할 때는 해당 규칙 버전과 남아 있는 근거를 사용한다.
