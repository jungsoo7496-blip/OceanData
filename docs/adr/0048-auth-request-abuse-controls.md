# ADR-0048: 인증 요청의 감사 크기와 갱신 비용 제한

- 상태: accepted
- 날짜: 2026-11-07
- 관련: 02번 요구사항 1.1, 1.2, 7.1~7.3 및 04번 요구사항 9.1, 9.2

## 맥락

긴 요청 경로가 인증 실패 감사에 그대로 저장됐다. 토큰 교환 호출 제한은 같은 IP에서 `client_id`를 바꾸면 새 키를 만들었고 키 저장소가 계속 커질 수 있었다. JWKS는 미확인 `kid`마다 잠금 안에서 다시 가져와 이미 캐시된 키로 검증할 수 있는 요청도 지연됐다.

## 결정

- `AUTH_FAILED`의 경로는 등록된 라우트 템플릿을 기록한다. 템플릿이 없으면 쿼리를 제외한 요청 경로의 앞 100개 유니코드 문자를 기록한다. 기존 감사 대상 인증 실패는 요청마다 해시 체인에 추가한다.
- 프로세스 내 각 `Limiter`의 키를 기본 4096개로 제한한다. 상한에서는 가장 오래 접근하지 않은 키를 퇴출한다. 토큰 교환은 접속 IP와 IP·`client_id` 조합을 각각 분당 30건 기준으로 검사한다. 초과하면 기존 429와 `Retry-After`를 반환한다.
- JWKS 갱신은 어댑터 인스턴스마다 한 번에 하나만 진행한다. 캐시 조회와 갱신 시작·결과 반영은 짧게 잠그고, IdP 호출과 키 파싱은 잠금 밖에서 한다. 유효기간 안의 알려진 키는 갱신을 기다리지 않고 검증에 사용한다. 미확인 `kid`의 강제 갱신과 실패 후 재조회에는 5초 간격을 둔다. 최초 조회와 만료 갱신이 진행 중이면 캐시를 사용할 수 없는 요청은 그 결과를 공유한다.
- 서명 키는 설정된 `IDP_ISSUER_URL` 또는 `IDP_INTERNAL_URL`의 JWKS 경로에서만 가져온다. `kid`는 키 선택에만 쓰고 JWT의 서명·발급자·대상·만료 검증을 적용한다. 캐시 기본 유효기간 300초와 기존 IdP 요청 제한시간을 사용하며, 갱신 실패로 만료된 키의 신뢰를 연장하지 않는다.

## 결과

갱신이 가능한 시점에 처음 발견한 새 키는 한 번 조회해 검증한다. 토큰 서명 검증 전에는 새 키의 `kid`와 임의 값을 구별할 수 없다. 직전 미확인 키 요청이 간격을 사용했거나 갱신이 이미 진행 중이면 새 키의 정상 토큰도 일시적으로 실패해 재시도가 필요하다.

호출 제한과 JWKS 갱신 간격은 프로세스 단위다. 키 퇴출 뒤에는 그 키의 호출 이력이 다시 쌓인다. 접속 IP는 배포 환경이 해석한 값을 사용하므로 프록시 뒤의 신뢰할 주소 설정과 여러 프로세스에 걸친 게이트웨이 제한은 운영 배포에서 다룬다.

감사 행의 요청별 기록 정책은 ADR-0049에서 별도로 논의한다. 기존 저장 구조를 사용하므로 마이그레이션은 없다.
