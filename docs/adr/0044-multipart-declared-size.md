# ADR-0044: 멀티파트의 신고 크기 강제

- 상태: accepted
- 날짜: 2026-11-06
- 관련: 04번 요구사항 1.1, 1.4, 1.5, 3.1, 4.1, 10.1

## 맥락

업로드 예약은 신고한 파일 크기에 따라 잡는다. 크기를 서명하거나 검사하지 않으면 작은 값으로 예약하고 더 큰 파트를 업로드해 쿼터를 넘길 수 있다. 업데이트 전에 발급한 URL은 유효기간 동안 길이 서명이 없다.

## 결정

신규·재개 URL은 계획한 파트 크기를 `Content-Length`에 서명한다. 끝 파트는 남은 길이를 서명한다. 빈 파일도 길이 0을 명시한다. 완료 전에 ListParts의 크기를 계획과 대조해 이전 URL이나 서명 검사를 지원하지 않는 저장소도 방어한다.

완료와 취소는 세션 행을 잠근 뒤 상태를 다시 읽는다. 완료에는 크기를 검사한 목록의 ETag를 사용한다. 검사 뒤 저장소에서 파트가 바뀌면 다른 ETag로 완료할 수 없다.

불일치가 확인되면 멀티파트를 중단하고 기존 ABORTED 정리 경로로 예약을 해제한 뒤 409와 `size_mismatch`를 반환한다. 크기를 확인할 수 없거나 정리가 실패하면 세션·예약을 유지하고 503을 반환한다. 파트 누락과 ETag 불일치는 세션을 보존한다.

저장 후 검증만 적용하면 이미 신고보다 큰 객체를 만든다. 서명만 적용하면 배포 이전 URL과 서명 미지원 저장소가 남는다. 두 검사 모두 적용하고 격리 사용량의 증감에는 동일한 자산 크기를 사용한다.

## 결과

SeaweedFS 3.80에서 정확한 길이(빈 파트 포함)는 성공하고, 길이가 달라지면 거부되는 것을 확인했다. 클라이언트는 서버가 반환한 파트 크기를 사용한다. 운영 스토리지는 선정 후 같은 시험이 필요하다. DB 구조 변경은 없다. 지시서 4번에서 완료·취소 경합의 기존 재현을 별도로 검증한다.
