# ADR-0042: 작업 큐·감시·목록 조회의 인덱스

- 상태: accepted
- 날짜: 2026-11-11
- 관련: 04번 요구사항 3.3, 05번 요구사항 1.2, 07번 요구사항 8.1, 09번 요구사항 2.1·5.2, 11번 요구사항 2.1·5.1, 마이그레이션 0024

## 맥락

워커의 작업 꺼내기와 업로드 만료 정리, 감시 규칙, 자산 및 관측값 목록이 반복 실행된다. 기존 제안의 수치는 사용한 데이터와 실행 스크립트가 남아 있지 않아 재측정했다.

## 결정

| 인덱스 | 검증한 경로 |
|---|---|
| `ix_jobs_claim_queued` | 평시와 대기 적체 시 작업 꺼내기 |
| `ix_uploads_uploading_expires` | 진행 중인 만료 업로드 정리 |
| `ix_uploads_created_at` | 감시 규칙의 업로드 실패율 |
| `ix_uploads_failed_updated` | 최근 업로드 실패 원인 집계 |
| `ix_assets_ingested_at` | 감시 규칙과 자산의 최근 실패 원인 집계 |
| `ix_assets_not_ready` | 기관별 처리 대기·격리 자산 목록 |
| `ix_observations_org_time` | 기관별 관측값 시간축과 회차 조회 |

일곱 인덱스 모두 기본 플래너가 대상 쿼리에서 사용했고 버퍼 사용량이 줄었다. 기존 전체 업로드 만료 인덱스는 진행 중 업로드의 부분 인덱스로 교체한다. 실제 `expires_at` 범위 조회는 해당 정리 경로에서 수행한다. 다운그레이드는 이전 인덱스를 복원한다.

## 측정

PostgreSQL 16.10에서 `shared_buffers` 163,848kB, `work_mem` 4,096kB, `random_page_cost` 4, 쿼리당 병렬 작업자 상한 2로 측정했다. 생성된 행은 자산 500,000, 작업 1,128,156, 업로드 271,719, 관측값 1,776,240, 감사 1,500,000, 이벤트 200,000, 계층 이동 3,005건이다. 평시 큐는 160건, 적체 큐는 40,160건이다. 평시는 적체 40,000건을 삭제하고 VACUUM한 뒤 별도로 비교했다.

애플리케이션이 실제로 실행하는 SQL과 매개변수를 포착했다. 각 쿼리를 한 번 데운 뒤 `EXPLAIN (ANALYZE, BUFFERS)` 7회 중앙값을 기록했다. 괄호 안은 공유 버퍼 hit와 read를 더한 블록 수다.

전체 감시 평가 시간, 쓰기 비용, 인덱스 크기, 계층 이동 계획 변화와 전 기관 운영자 조회는 재측정 못 함. 관측값 인덱스는 기관·시간 범위를 좁히며 회차 조건과 나머지 정렬 키는 별도로 처리된다.

## 재현과 롤백

시험용 PostgreSQL 연결이 설정된 컨테이너에서 저장소 루트와 백엔드를 Python 경로에 두고 실행한다.

```powershell
docker exec -u 10001 -w /repo -e PYTHONPATH=/repo/backend -e PYTHONDONTWRITEBYTECODE=1 oceandata-meta03-test-python python tools/hot_path_benchmark.py
```

`tools/hot_path_benchmark_seed.sql`은 새 `marine_perf_*` DB의 0023에서 합성 데이터를 생성한다. 도구는 데이터가 든 DB를 0024로 올렸다가 0023으로 내려 행 수와 인덱스 정의를 대조한 뒤 임시 DB를 삭제한다. 이번 측정에서 Python 기동을 포함한 업그레이드는 2.57초, 다운그레이드는 1.37초였다. 일반 CREATE INDEX가 대상 테이블의 쓰기를 잠그므로 운영 적용은 점검 시간에 한다.
