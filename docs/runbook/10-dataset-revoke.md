# 10 데이터셋·이용 권한 철회

**판단 기준:** 제공기관의 공유 철회 요청, 약정 위반 의심, 근거 손상·비식별 미탐 발견.

**자동 대응:** 철회하면 새 다운로드 URL 발급이 즉시 멈추고(410), 이용기관에 "이미 받은 파일은 회수되지 않음"과 파기 확인 요청이 간다.
제공기관이 공유 등급을 낮추며 REVOKE_NOW를 고르면 그 자산이 든 버전의 권한이 자동 철회되고, 새 버전에서는 규칙이 그 자산을 뺀다.

**사람이 할 것**
1. 제공기관 ORG_ADMIN 또는 운영자: '이용 신청' 화면 → 권한 철회 또는 `POST /v1/grants/{id}/revoke`.
2. 자산 단위: `POST /v1/assets/{id}/share-requests` (낮은 등급 + existing_grant_handling).
3. 이용기관의 파기 확인(`destruction-confirmation`) 제출 여부를 추적, 기한 안에 없으면 약정 절차로.
4. 필요하면 새 데이터셋 버전(해당 자산 제외)을 만든다.

**완료 확인:** 권한 상태 REVOKED, 배포 요청 410, 이용 이력에 REVOKED, 파기 확인 시각 기록.
